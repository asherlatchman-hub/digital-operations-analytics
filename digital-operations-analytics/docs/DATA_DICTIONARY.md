# Data dictionary

All measurements are synthetic examples.

## service_daily.csv

| Column | Meaning |
|---|---|
| date | Calendar day in `YYYY-MM-DD` format |
| service | Fictional business application |
| team | Fictional business/IT function |
| users | Simulated service user base; not the number affected by a particular incident |
| requests | Number of simulated requests recorded that day |
| avg_latency_ms | Synthetic average response time in milliseconds |
| error_rate_pct | Synthetic daily average percentage of requests with errors |
| error_slo_pct | Configured error-rate ceiling for the simulated services |

## incidents.csv

| Column | Meaning |
|---|---|
| incident_id | Unique simulated incident reference |
| service | Application related to the incident |
| opened_at | Timestamp of incident opening |
| priority | Simulated severity label (P1-P4) |
| status | Incident status as recorded in the static export |
| affected_users | *Estimated* impact, not a count of unique users across incidents |
| priority_score | A historical value from a separate synthetic incident export or additional sample records; the dashboard does **not** calculate these scores |
| issue_type | Type of anomalous metric |
| summary | Short fictional incident description |
| record_origin | Shows whether the row came from the separate synthetic export or the additional example records |

## Important analytical distinction

`error_rate_pct` in the daily table is a **daily average**. The incident data contains separate peak descriptions in its text. They are not interchangeable, and data from the two sources was not generated by the same model. A JOIN on service and date puts the records side by side; it does **not** prove causation.
